## El problema

Los modelos aprenden el promedio de internet. Sin dirección entregan el mismo hero centrado, el mismo degradado violeta, las mismas tres tarjetas con icono y el mismo copy vacío. Eso no se arregla con CSS. Falta **concepto, especificidad y revisión**.

- **Concepto antes que píxeles.** Tres direcciones distintas, una elección argumentada, un *signature move*.
- **Nunca una sola fuente.** Toda dirección mezcla tres diseñadores documentados, cada uno dueño de un eje.
- **Oficio verificable.** Tipografía, color, composición, motion, accesibilidad y rendimiento con umbrales explícitos y scripts que los miden.
- **Revisión adversarial.** Diez puertas, un Delivery Gate con evidencia en cada línea y un Tribunal con veto.
- **Cero fabricación.** Una métrica, logo, cita, premio o "enviado con éxito" sin nada cierto detrás es P0.

Cada modelo es una página con su propio CSS y JS. El piso sigue valiendo: contraste real, recorrido por teclado, movimiento reducido diseñado como imagen fija, todo el texto legible sin JavaScript y ningún botón que finja enviar. Estudios, personas y precios son ficticios y están rotulados. Las 13 plantillas de scaffold siguen en la skill (`new-project.mjs --list`).

## Cómo funciona

![El flujo de BUREAU: intake, concepto, dirección, build, refinamiento, motion, QA y revisión](docs/assets/diagrams/workflow.svg)

1. **Intake.** La verdad del producto va a `BUREAU.md`: público, oferta, pruebas con fuente, no-objetivos.
2. **Concepto.** Primero un relevamiento de cinco referencias verificadas entre las 25 fuentes (la fuente que no pueda verificarse se salta y se toma la siguiente), con el patrón común y la ruptura nombrados. Después tres direcciones, cada una una mezcla de tres linajes. La elegida va a `blend.md`.
3. **Dirección.** `DESIGN.md` con tokens normativos, dials ENERGY / RHYTHM / MOTION y el mundo visual.
4. **Build y refinamiento.** Siete pasadas, de la estructura al detalle, cada una con evidencia.
5. **QA y revisión.** Audit estático, audit visual en cinco anchos, diez puertas, Delivery Gate y Tribunal.

## El circuito

![El circuito de revisión: Gate Zero, nueve puertas ponderadas y el Tribunal](docs/assets/diagrams/circuit.svg)

| Veredicto | Nota |
|---|---:|
| Award Track | ≥ 90 |
| Pass | 82–89 |
| Conditional | 72–81 |
| Fail | < 72 |

Cualquier P0, cualquier puerta por debajo de 3,5/5, evidencia ausente, fuente cambiada después de la revisión o un Delivery Gate sucio **reprueba**. Un 95 con un P0 de accesibilidad es Fail. Un Tribunal en el mismo contexto que construyó el trabajo se declara *degraded* y no llega a Award. El bucle del jurado tiene un límite de 10 minutos: los jurados votan en paralelo, cada ronda se puntúa y la mejor ronda dentro del plazo es la decisión.

## Anti-AI-slop

| Nivel | Severidad | Renuncia |
|---|---|---|
| **Floor** | P0 | nunca |
| **Reflex** | P1 | ID de la regla + un motivo de 20+ caracteres sobre esta página |
| **Finish** | P2 | respondido, nunca bloquea |

```bash
node skill/scripts/audit.mjs .                 # 32 reglas de regex + chequeos de proyecto
node skill/scripts/visual-audit.mjs http://localhost:4173 --out .bureau/qa
node skill/scripts/divergence.mjs index.html --templates
```

El detector cubre el subconjunto mecánico: degradado violeta, envío falso, enlace muerto, contenido oculto sin JS, puntuación de plantilla, fuente por defecto, autoplay y más. Cada regla tiene una prueba que falla y una que pasa. Un audit limpio no es calidad: sin dials y sin mundo, la página es un vacío limpio y reprueba las puertas 1 y 2.

[Taxonomía anti-slop →](docs/es/antislop.md)

## Linaje y mezcla

Ninguna dirección sale de una sola fuente. El canon tiene cuarenta diseñadores citados por su obra documentada, de Müller-Brockmann y Tschichold a Lina Bo Bardi, Reid Miles y Susan Kare. Cada mezcla usa un **dominante** (50–60%, estructura), un **contrapunto** (25–35%, expresión, tirando en contra) y un **acento** (10–20%, un comportamiento), más un ingrediente que solo el tema tiene.

## Instalación

```bash
git clone https://github.com/acf1210/bureau.git
cd bureau

# siempre previsualiza primero
bash installers/install.sh --agent all --scope user --dry-run

# instala
bash installers/install.sh --agent all --scope user
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File installers/install.ps1 -Agent all -Scope user -DryRun
powershell -ExecutionPolicy Bypass -File installers/install.ps1 -Agent all -Scope user
```

Reinicia el agente e invoca `/bureau`, o pide con naturalidad: *"Usa BUREAU para crear el sitio de mi marca."*

| Host | Skill | Extra |
|---|---|---|
| Claude Code | `~/.claude/skills/bureau` | `~/.claude/commands/bureau.md` |
| Codex | `~/.codex/skills/bureau` | bloque opcional en `AGENTS.md` |
| Antigravity | `~/.gemini/config/skills/bureau` | regla `model_decision` |
| Hermes | `~/.hermes/skills/creative/bureau` | — |

## Primer uso

```bash
node skill/scripts/doctor.mjs
node skill/scripts/new-project.mjs --list
node skill/scripts/new-project.mjs mi-sitio --template restaurant-table
cd mi-sitio

node ../skill/scripts/audit.mjs . --out .bureau/evidence/audit.json
node ../skill/scripts/visual-audit.mjs http://localhost:4173 --out .bureau/qa --full --motion
node ../skill/scripts/review.mjs --status
```

El scaffold crea `BUREAU.md`, `DESIGN.md` (con linaje y dials), `MOTION.md`, `.bureau/config.json` y las carpetas de evidencia. La página empieza como copia de la plantilla: antes de la puerta 2 debe alejarse de ella.
